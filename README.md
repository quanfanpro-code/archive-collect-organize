# 零散资料整理

整理用户指定目录中的零散资料，让文件能按主题、用途和对象查找。输入可以混有散文件、旧文件夹、压缩包和已经整理过的资料；不限定行业、文件格式，也不预设分类名称与数量。

整理必须实际完成分类归位。只解压、只给分类方案或仍按收件包分成几堆，都不能宣称完成整理。用户仅要求解压或方案时，按其明确范围交付。

## 怎么使用

向支持技能的AI提供资料目录和要求即可，例如：“整理这个目录，按实际资料归类，保留原文件，最后给我归位清单。”有现成目录模板、禁止展开的包或其他约定时一并提供。AI负责盘点、归纳分类、生成完整计划、移动和核验，用户无需写规则或运行命令。

- 有模板时沿用模板；没有模板时依据实际资料归纳主题与用途。
- 目录和文件名不足以判断时，在授权范围内读取少量必要线索；仍不明确就保留原位置并列待确认，先完成明确部分。
- 合并同类资料，同时保留对象、期间、事项、来源和成套附件的必要层次，不把目录全部摊平。
- 已有分类继续使用，已有解压结果不重复生成副本；再运行只处理新增和未完成事项。

## 文件保护

保留原文件名和原始压缩包。默认不跨目录去重、不按时间选新版；同名、同内容或较新时间均不能单独证明资料互相替代。同一完整目标路径存在冲突时，增加有依据的来源或事项子目录保存双方。

备份遵循本次会话约定。用户明确以原压缩包作备份、要求直接移动时，核实涵盖范围后不再复制整目录；未包含的散文件不能假定已经备份。脚本不删除文件或目录、不覆盖既有文件、不为读取某种格式安装额外环境。

## 工具分工

| 工具 | 职责 |
|---|---|
| `scripts/archive_sync.py` | 按需展开ZIP及补缺，默认保留来源目录、包名和包内路径；只是中间步骤 |
| `scripts/业务归类.py` | 按已核对的逐文件计划移动归位，预检漏项、改名、越界、目标冲突并回读核验 |
| `scripts/resolve_conflicts.py` | 兼容历史补文件；普通整理不调用，另行授权后才启用`--by-time` |

完整计划格式、预检与执行方式见 [SKILL.md](SKILL.md)。已归位或暂不能确定归属的文件，可在清单中以相同source、target登记原地保留。执行成功只证明清单操作完成，不能替代语义归属、压缩包展开状态和最终验收的判断。

ZIP工具默认区分不同来源包，核对后才通过显式映射合并落点，禁止解压写入已归属工具的内部报告区。兼容UTF-8和GBK中文条目名，跳过包内系统元数据；`config/mapping.example.json`支持archives、rules、scatter和exclude。exclude可使用相对根目录的完整包路径，也兼容旧的包名写法。内嵌包、损坏包、加密包及不支持的格式均保留原件并单列处理状态；展开或完整性失败后不再执行可选的散文件分流。

## 报告与异常

工具先创建带自身归属标记的内部报告目录。用户已有同名文件夹时另建不冲突的位置，不按“整理报告”“旧版本”等名称跳过用户资料。AI应先用`archive_sync.report_root(root)`取得实际路径，再存放计划。

业务归位报告每次新建独立子目录，包含`归位明细.csv`、`结果.json`及执行时的移动日志；不覆盖历史报告。空的来源目录可集中收存，不自动删除。回读不符或文件变化时停止后续相关写入；移动后的收尾异常也保留已做动作及失败记录。

完成时交付：

- 实际分类及各类数量，说明业务资料、原始包与内部报告的统计口径。
- 原位置到新位置的逐文件清单，以及大小和内容指纹核验结果。
- 待确认、未展开、失败和按要求保留的事项；区分明确部分已完成与全部完成。

## 验证范围

`test-prompts.json`使用三类通用任务：陌生混杂目录自主分类、按用户模板处理复杂归属、已有分类下的增量整理。评估使用不同领域的隔离样本，不把具体目录名或文件格式当标准答案。

自动验证覆盖跨目录文件保留、同名包的来源区分、用户目录与内部报告区分、预检阻断、异常留痕和文件完整性等行为。使用本机已核实的Python运行`tests/test_skill.py`；测试保留样本，可用`ACO_TEST_ROOT`指定存放目录，不自动删除。

三类场景及自动验证只能证明已覆盖的行为，不代表能读取所有文件格式或在所有目录上零错误。资料归属不明确或处理受限时，保留原物、记录范围并如实报告。
